| Case group | Documents | Expected fields | Purpose |
|---|---:|---:|---|
| Supported Fire Safety NOCs | 6 | 18 | Issue date, expiry date, issuing authority |
| Unsupported month-name expiry wording | 4 | 4 | Confirm deliberate abstention/manual review |

The four unsupported Fire Safety NOC cases use month-name expiry wording outside the current parser patterns. All four were routed to `manual review required` and did not produce an expiry-date claim. This is intentional: the prototype abstains rather than treating a filename or unsupported date phrase as verified evidence.

## Reproduce

Run from the repository root:

```bash
python backend/evaluate_document_extraction.py
python backend/evaluate_document_extraction.py --report-path docs/EXTRACTION_EVALUATION.md
```

The script generates the PDFs and expected field labels, then calls the current `global_document_extractor`. GitHub Actions runs it in the Python 3.13 backend job after the full backend suite.

## Limitations and next measurement

- Documents are synthetic PDFs generated by code; they do not represent the layout, scan quality, language, or variability of real institutional filings.
- This run measures the current supported text-stream patterns only; it does not measure Tesseract OCR, unreadable image scans, live issuer checks, rule-engine correctness, or reviewer time.
- “0 wrong” is limited to these 50 labelled expected field slots; it should not be generalized beyond this fixture set.
- The next evaluation should broaden layouts and date formats, include multi-page PDFs and realistic scanned images, and separately report wrong, correct, and abstained fields for text extraction and OCR.
